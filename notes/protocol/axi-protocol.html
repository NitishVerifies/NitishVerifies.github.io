AXI Protocol

Interview-focused notes for AMBA AXI: channels, handshakes, bursts, responses, ordering, and verification checks.

AXI At A Glance

AXI is a high-performance memory-mapped protocol used to connect masters, interconnects, and slaves in an SoC. It separates address, data, and response activity into independent channels so reads and writes can be pipelined.

Five Independent Channels

  • AW: Write address channel. Carries write address and burst attributes.
  • W: Write data channel. Carries write payload, byte strobes, and WLAST.
  • B: Write response channel. Returns completion status for a write transaction.
  • AR: Read address channel. Carries read address and burst attributes.
  • R: Read data channel. Returns read payload, response, and RLAST.

VALID/READY Handshake

A transfer happens only when VALID and READY are high on the same clock edge. The source drives VALID when information is available, and the destination drives READY when it can accept that information.

  • VALID must not wait for READY.
  • Payload must remain stable while VALID is high and READY is low.
  • READY may be asserted before, during, or after VALID.

Write Transaction Flow

A write uses AW, W, and B. The master sends the write address on AW and write data beats on W. The slave returns one B response after the full write burst is accepted. 

AW: address + burst control
W : data beat 0 ... data beat N with WLAST on final beat
B : single write response

Read Transaction Flow

A read uses AR and R. The master sends the read address and burst attributes on AR. The slave returns one or more R beats, marking the final beat with RLAST.

Burst Types

  • FIXED: Address remains constant for every beat.
  • INCR: Address increments by transfer size for each beat.
  • WRAP: Address increments but wraps around a naturally aligned boundary.

Response Types

  • OKAY: Normal successful access.
  • EXOKAY: Exclusive access success.
  • SLVERR: Slave accepted the access but reported an error.
  • DECERR: Decode error, usually from an unmapped address region.

AXI4 vs AXI4-Lite

  • AXI4 supports bursts, IDs, outstanding transactions, and high-throughput pipelining.
  • AXI4-Lite is simpler: single-beat register accesses, no bursts, and commonly used for control/status registers.

Verification Checklist

  • VALID/READY payload stability under backpressure.
  • Correct WLAST and RLAST timing for burst length.
  • Address alignment and legal burst boundary behavior.
  • Response checking for OKAY, SLVERR, and DECERR scenarios.
  • Outstanding transaction tracking and ID-based ordering rules.
  • Reset behavior: no stale VALID, responses, or scoreboard entries after reset.

Common Interview Points

  • AW and W channels are independent; data can arrive before, after, or alongside the address depending on design support.
  • A write response should be generated only after the relevant address and write data have been accepted.
  • Backpressure must be tested independently on every channel.
  • Scoreboards should model expected memory/register state and match responses per transaction ID.
